# TG 频道到公众号全流程发布系统实现方案

日期：2026-07-11

## 目标

实现一套本地运行的发布流水线：

1. 从 Telegram 频道 `https://t.me/TechnologyNewsSyncAssistant` 采集消息、图片、视频和引用链接。
2. 按日期保存为本地 Markdown 文章，并将每篇文章关联的图片、视频保存在同一目录。
3. 将 Markdown 文章转换为适合微信公众号编辑器的内容。
4. 在用户提前登录微信公众号后台的情况下，通过浏览器自动化创建公众号草稿，并在确认后发布。
5. 支持不经过 Telegram 的公开网页教育资讯源采集，面向“春晖学府”等教育账号生成可发布 Markdown。

默认策略：自动化保存为公众号草稿，不默认自动点击“群发/发布”。发布动作需要显式参数或人工确认，避免误发。

采集策略：第一版不回溯 Telegram 历史内容，程序运行后监听频道新消息。需要发布的旧内容可以由用户在程序运行后重新发送到频道，再由系统按新消息处理。

## 总体架构

```text
Telegram 频道
    |
    v
采集器 tg_collector
    |
    v
规范化消息 ArticleDraft
    |
    +--> 媒体下载 media_downloader
    +--> 链接解析 link_enricher
    |
    v
Markdown 渲染 md_renderer
    |
    v
发布内容/YYYYMMDD/*.md + 图片 + 视频
    |
    v
公众号发布器 wechat_publisher
    |
    v
微信公众号后台草稿/发布
```

## 技术选型

### Telegram 采集

第一版优先使用 Telegram Bot API 监听新频道消息。

原因：

- 用户已确认历史内容可以不采集，需要发布的旧内容可以在程序运行后重新发送。
- Telegram Bot API 支持接收频道新帖 `channel_post` 和编辑后的频道帖 `edited_channel_post`。
- 使用 Bot API 不需要创建 Telegram developer app，也不需要 `api_id` 和 `api_hash`。
- 当前 `my.telegram.org` 创建应用持续返回泛化 `ERROR`，切换到 Bot API 可以降低实施阻塞。

需要用户提供或配置：

- `[telegram].bot_token`，从 BotFather 获取。
- 频道用户名：`TechnologyNewsSyncAssistant`。
- 确认 `TechnologyNewsSyncAssistant_bot` 已加入频道并具备管理员权限。

Bot API 获取不到任意历史消息，只处理程序运行后 Telegram 推送到 bot 的新消息。Telegram 服务器端会短暂保留未取走的更新，但不把它作为历史采集能力依赖。

如果未来确实需要回溯频道历史，再增加 MTProto 用户客户端方案，推荐 Python `Telethon`。该方案需要 `TG_API_ID`、`TG_API_HASH` 和 `TG_PHONE`。

`TG_API_ID` 和 `TG_API_HASH` 备选获取方式：

1. 打开 `https://my.telegram.org/`。
2. 用要采集频道的 Telegram 手机号登录。
3. 进入 `API development tools`。
4. 如果还没有应用，创建一个应用；应用名称可以填写 `tgexporter`，平台可选择 `Desktop` 或按页面可选项填写。
5. 创建后页面会显示 `api_id` 和 `api_hash`，分别对应本项目配置里的 `TG_API_ID` 和 `TG_API_HASH`。

真实凭据不建议写入 `docs/实现方案.md`。收到凭据后，建议统一保存到本地 `config.local.toml`，并通过 `.gitignore` 排除提交；方案文档只保留获取方式和字段说明。

### 本地内容保存

输出目录沿用需求中的规则：

```text
E:\PerSourceCodeStore\github\chengjinxt\tgexporter\发布内容\YYYYMMDD
```

每篇文章及其媒体使用统一前缀：

```text
YYYYMMDD_当天序号_标题.md
YYYYMMDD_当天序号_PIC_001_标题.jpg
YYYYMMDD_当天序号_PIC_002_标题.png
YYYYMMDD_当天序号_VID_001_标题.mp4
```

文件名清理规则：

- `"` 替换为 `“`
- `:` 替换为 `：`
- `/` 替换为 `、`
- Windows 不允许的 `\ * ? < > |` 替换为安全字符或删除
- 连续空格压缩为单空格
- 文件名过长时保留标题前半部分，并保证同一篇文章的前缀一致

### 公众号发布

优先实现浏览器自动化发布器，使用 Python `Playwright`：

- 启动持久化浏览器用户目录：`runtime/wechat-profile`
- 打开 `https://mp.weixin.qq.com/`
- 如果未登录，暂停等待用户扫码或确认登录
- 进入图文素材编辑页
- 填入标题、正文，并按 Markdown 顺序通过公众号“本地上传”插入正文图片
- 封面优先从正文里已上传的图片中选择
- 标题输入、图片上传、封面选择、新增子图文等操作加入随机停顿，避免过快连续操作
- 自动保存为草稿后停在编辑器供人工检查，由用户决定是否预览或发表
- 可选参数才执行发布动作

`runtime/wechat-profile` 是 Playwright 测试浏览器的独立用户目录，不等同于系统默认 Chrome/Edge。公众号后台内容是否持久保存，以后台“保存为草稿”等操作为准；本地浏览器 profile 只保存登录态和浏览器会话数据。

公众号后台页面经常调整，发布器需要保留调试能力：

- 自动截图：`runtime/screenshots`
- Playwright trace：`runtime/traces`
- 失败时输出当前步骤、页面 URL 和截图位置

如果后续有公众号官方 API 权限，也可以增加 API 发布适配器，但第一版以“打开浏览器，用户已登录账号”的模式为主。

## 数据模型

### ArticleDraft

每条或一组 Telegram 消息会被整理成一篇文章草稿：

```json
{
  "source": "telegram",
  "channel": "TechnologyNewsSyncAssistant",
  "message_ids": [12345],
  "grouped_id": null,
  "published_at": "2026-07-11T10:00:00+08:00",
  "date_key": "20260711",
  "daily_index": 1,
  "title": "文章标题",
  "text": "正文文本",
  "links": [
    {
      "name": "引用名称",
      "url": "https://example.com"
    }
  ],
  "media": [
    {
      "kind": "image",
      "path": "20260711_001_PIC_001_文章标题.jpg",
      "source": "telegram"
    }
  ],
  "status": "rendered"
}
```

### 状态库

使用 SQLite 保存增量状态：

```text
data/state.sqlite
```

主要记录：

- 已采集频道
- 已处理 message id
- 相册组 grouped id
- 本地文章路径
- 发布状态：`collected`、`rendered`、`drafted`、`published`、`failed`
- 失败原因和重试次数

这样可以避免重复下载、重复生成和重复发布。

## Telegram 采集规则

1. 默认启动频道新消息监听，不回溯历史消息。
2. 如果消息存在 `grouped_id`，将同一个相册组聚合成一篇文章。
3. 提取正文：
   - 优先使用消息正文或媒体 caption。
   - 转发来源如果可见，记录到 Markdown frontmatter。
4. 生成标题：
   - 优先取正文第一行中最像标题的内容。
   - 如果正文第一行是 URL，则使用网页标题。
   - 如果无法判断，使用 `Telegram消息_消息ID`。
5. 提取引用：
   - 正文中出现 URL 时，解析网页 title，形成 `名称` 和 `地址`。
   - Markdown 中单独输出“引用来源”区块。
   - `mp.weixin.qq.com` 不进入引用来源和来源域名统计；如果它来自 Telegram 隐藏链接，或正文中形如 `Tech 星球 (https://mp.weixin.qq.com/...)` 的普通文本链接，则保留在正文中作为 Markdown 超链接，发布公众号时转成可点击链接。
6. 下载媒体：
   - 图片保存为 `PIC`
   - 视频保存为 `VID`
   - 保留原始扩展名，无法识别时根据 MIME 类型补齐。
7. 根据引用或地址补图：
   - 如果 Telegram 消息本身没有图片，但正文包含 URL，则先读取 OpenGraph 图片，再读取网页正文 `img` / 懒加载图片候选。
   - `mp.weixin.qq.com` 作为特殊来源处理，会提取页面中的 `mmbiz.qpic.cn` 图片作为正文配图候选。
   - 只下载可公开访问、尺寸合理且视觉信息足够的图片，跳过 Logo、二维码、频道头像、纯色或渐变占位图。
   - 网页候选都不合格时，使用 Playwright 打开来源网页，优先截取页面最大新闻图；仍无合格图片时截取正文区域。
   - 浏览器截图仍失败时，再尝试多张 Google 图片搜索候选。
   - 最后才生成本地占位封面，避免公众号图文缺少封面。
   - 补图来源可能标记为 `web_og_image`、`web_capture` 或 `google_image_search`。
   - 常见来源域名的图片/视频获取方法维护在 `docs\来源网站资源获取策略.md`。

## Markdown 输出格式

每篇文章生成一个 Markdown 文件：

```markdown
---
title: 文章标题
date: 2026-07-11 10:00:00
source: telegram
channel: TechnologyNewsSyncAssistant
message_ids:
  - 12345
status: rendered
---

# 文章标题

正文内容

![图片说明](20260711_001_PIC_001_文章标题.jpg)

视频： [20260711_001_VID_001_文章标题.mp4](20260711_001_VID_001_文章标题.mp4)

## 引用来源

- 名称：https://example.com
```

Markdown 文件用于本地留档、人工审阅和后续发布输入。

## 公众号内容转换

发布前将 Markdown 转换为公众号编辑器更容易接受的 HTML：

1. Markdown 标题写入公众号标题栏，正文里跳过重复标题，标题栏自动去掉 emoji/图标字符。
2. Markdown 正文按段落转 HTML，并保留原始段落顺序。
3. 本地图片按 Markdown 出现顺序逐张通过公众号“图片 -> 本地上传”插入正文。
4. 封面从正文里已上传的图片中选择，优先使用文章首图。
5. 本地视频不直接插入为 HTML `<video>` 控件，后续通过公众号视频号/素材视频流程处理。
6. 正文内 Markdown 链接 `[文字](https://...)` 转为公众号可点击超链接，其中 `mp.weixin.qq.com` 链接保留在正文，不单独抽取为引用来源。
7. 引用来源单独排版。

第一版不追求复杂排版，优先保证内容完整、图片和视频对应正确、可稳定保存草稿。

## 命令行设计

使用一个本地 CLI 入口：

```powershell
tgexporter listen --channel TechnologyNewsSyncAssistant
tgexporter listen --save-dir "E:\PerSourceCodeStore\github\chengjinxt\tgexporter\发布内容"
tgexporter publish-wechat --article ".\发布内容\20260711\20260711_001_文章标题.md"
tgexporter publish-wechat --article ".\发布内容\20260711\20260711_003_主图文.md" ".\发布内容\20260711\20260711_001_子图文.md" ".\发布内容\20260711\20260711_002_子图文.md" --auto-fill
tgexporter publish-wechat --article-dir ".\发布内容\20260716" --auto-fill
tgexporter publish-wechat --article-dir "E:\PerSourceCodeStore\github\chengjinxt\tgexporter\发布内容\20260718"
.\dist\tgexporter-portable\tgexporter.exe publish-wechat --article-dir "E:\PerSourceCodeStore\github\chengjinxt\tgexporter\发布内容\20260718"
.\dist\tgexporter-portable\tgexporter.exe --draft
tgexporter source-login --url "https://x.com/SpaceXAI/status/2076692402442846289" --timeout 600
tgexporter collect-web --group chunhui-xuefu --limit 1
tgexporter collect-web --group chunhui-xuefu --limit 1 --interval-seconds 3600
tgexporter collect-web --group chunhui-xuefu --limit 5 --backfill
tgexporter stats-domains
tgexporter stats-domainsstats-domains
tgexporter run --channel TechnologyNewsSyncAssistant --draft
```

命令说明：

- `listen`：监听 Telegram 频道新消息，采集文本和媒体，写入状态库；`--save-dir` 可覆盖本次运行的保存根目录，仍会在根目录下按日期创建子目录。
- `--draft`：绿色版一键全天流程。长期运行监听新消息，默认在当前根目录下的 `发布内容\YYYYMMDD` 生成文章；只判断当天日期目录，过去日期目录不会被自动处理；每满 8 篇自动保存一条公众号多图文草稿；当天不足 8 篇但至少 1 篇时，在本机时间 23:00 自动保存草稿。草稿保存成功后会把本批 Markdown 及引用资源移动到 `第1批`、`第2批` 等子目录。
- `publish-wechat`：将单篇或多篇 Markdown 填入公众号草稿；多篇时第一篇是主图文，后续文件依次作为子图文追加。公众号每次最多 8 篇，`--article-dir` 超过 8 篇时自动分批发布。
- `source-login`：打开来源站点专用持久化浏览器，用于 X、微博、The Information 等可能需要登录或订阅的页面；登录态默认保存在 `runtime\source-profile`。
- `collect-web`：直接从公开网页源采集资讯并生成 Markdown。当前默认源组 `chunhui-xuefu` 采集教育部官网工作动态，跳过单纯高校人事任免，适合“春晖学府”发布教育政策、教师培养、资助、升学等服务型图文；默认只追最新增量，`--backfill` 才向旧列表回扫，`--interval-seconds` 大于 0 时常驻定时采集。
- `stats-domains`：统计已生成文章记录中的引用来源域名；`stats-domainsstats-domains` 作为误输兼容别名保留。
- `run`：执行新消息监听、渲染、发布草稿的完整流程。

`tgexporter` 是 Python 包安装后的控制台命令；未安装时可在项目根目录使用 `python tgexporter.py ...`。本地开发推荐执行 `python -m pip install -e .` 注册命令入口。

`--article-dir` 只读取指定目录直接子级的 `.md` 文件，不递归进入子目录。目录超过 8 篇时，每批保存草稿成功后，将本批 Markdown 和 Markdown 引用到的本地图片、视频、附件移动到 `第1批`、`第2批` 等子目录，避免下次重复发布。

Windows exe 打包：

```powershell
.\scripts\build_exe.ps1
```

生成：

```text
dist\tgexporter-portable\tgexporter.exe
dist\tgexporter-portable.zip
```

打包采用 PyInstaller onedir 绿色目录模式，Python 依赖、Playwright 驱动和 Chromium 浏览器都放在 `dist\tgexporter-portable` 目录中，不使用 onefile 自解压模式，避免每次运行都解压到 `_MEI...` 临时目录。绿色目录保留稳定的 `runtime\wechat-profile`，公众号扫码登录态可跨运行复用；如果绿色目录仍在项目 `dist` 下，程序会自动向上查找项目根目录的 `config.local.toml`、`data` 和 `runtime`。

## 实施阶段

### 阶段一：工程骨架和本地 Markdown 生成

交付内容：

- Python 项目结构
- 配置加载
- 文件名清理和命名规则
- Markdown 渲染器
- SQLite 状态库
- 单元测试

验收：

- 能用模拟数据生成符合命名规则的 Markdown、图片和视频引用。

### 阶段二：Telegram 真实采集

交付内容：

- Bot API token 配置
- 频道新消息 `channel_post` 监听
- 编辑消息 `edited_channel_post` 处理
- 相册组聚合
- 图片和视频下载
- URL 提取和网页标题解析

验收：

- 程序运行后，能采集用户重新发送到 `TechnologyNewsSyncAssistant` 的新内容。
- 能在 `发布内容/YYYYMMDD` 下生成文章和媒体文件。

### 阶段三：公众号草稿发布

交付内容：

- Playwright 持久化浏览器登录
- 打开公众号后台
- 创建图文草稿
- 填入标题和正文
- 上传图片
- 尝试上传视频
- 保存草稿
- 失败截图和 trace

验收：

- 用户提前登录后，命令能创建一篇公众号草稿。
- 失败时能定位到具体页面和步骤。

### 阶段四：全流程命令和安全发布

交付内容：

- `run` 一键流程
- 发布前预览和确认
- 跳过已发布文章
- 重试失败任务
- 可选自动发布参数

验收：

- 程序运行期间收到的新消息可以完成：Telegram 采集 -> 本地 Markdown -> 公众号草稿。
- 不重复发布同一篇文章。

## 风险和边界

1. Bot API 不用于回溯历史消息，程序启动前的旧内容需要用户重新发送到频道。
2. 微信公众号后台没有稳定公开的浏览器自动化接口，页面更新可能导致选择器失效，因此需要保留截图和 trace。
3. 公众号视频上传可能受账号权限、大小、格式和审核限制影响。第一版会尽量自动上传，失败时保留本地视频路径并提示人工处理。
4. 自动点击“发布/群发”风险较高，第一版默认只保存草稿。
5. 网页补图依赖目标网站是否提供 OpenGraph 图片，不保证每个链接都有可用图片。
6. 如果未来要采集 Telegram 历史内容，需要重新启用 Telethon 路线，并解决 `api_id` 和 `api_hash` 获取问题。
