# 使用说明

## 本地配置

真实配置统一保存在 `config.local.toml`，不要提交到 Git。`.env` 已不再作为程序配置文件读取，避免同一项配置分散在两个文件里。

当前需要的关键项：

```toml
[telegram]
bot_token = "从 BotFather 获取的 token"
channel = "TechnologyNewsSyncAssistant"
poll_timeout_seconds = 30
proxy_url = "http://127.0.0.1:7890"

[output]
base_dir = "发布内容"
timezone = "Asia/Shanghai"

[wechat]
profile_dir = "runtime/wechat-profile"
default_mode = "draft"
author = "成进学堂"

[wechat_accounts.default]
profile_dir = "runtime/wechat-profile"

[wechat_accounts.movie4k]
profile_dir = "runtime/wechat-profile-movie4k"

[source]
profile_dir = "runtime/source-profile"

[web_sources]
default_group = "chunhui-xuefu"
interval_seconds = 3600
max_articles_per_run = 1

[tech_digest]
output_dir = "发布内容/科技日报"
target_channel = ""
schedule_at = "20:00"
timezone = "Asia/Shanghai"
articles_per_core = 2
daily_limit = 16
candidates_per_source = 12

[tech_digest.translation]
provider = "libretranslate"
model_dir = "runtime/translation-models"
# 以下四项仅在 provider = "openai" 时使用。
endpoint = "https://api.openai.com/v1/chat/completions"
model = ""
api_key_env = "OPENAI_API_KEY"
timeout_seconds = 90

[routes.movie4k]
output_subdir = "4K影视屋"
account = "movie4k"
cover_brand = "剪辑探索者"
batch_size = 2
match_usernames = ["dianying4K"]
match_titles = ["4K影视屋"]
```

`tgexporter` 会优先直连目标网站；直连不可用时，再自动尝试 `[telegram].proxy_url` 配置的 HTTP 代理和操作系统代理。代理部署在路由器、网络本身已经可达时，即使配置里还保留着失效的本地代理地址，也不会阻塞正常访问。使用 FlClash、Clash、v2ray 等本地代理时，仍可填写例如 `http://127.0.0.1:7890`；不需要代理时留空即可。

`[web_sources].default_group = "chunhui-xuefu"` 用于“春晖学府”这类非 Telegram 来源账号。默认源组会采集教育部官网工作动态，跳过单纯高校人事任免，优先生成适合学生、家长、教师和学校关注的教育资讯 Markdown。

## 打包绿色版

在项目根目录运行下面命令，会生成 `tgexporter-portable` 绿色目录和 zip 包：

```powershell
.\scripts\build_exe.ps1
```

首次在开发机打包前安装构建依赖：

```powershell
python -m pip install -e ".[wechat,local-translation]"
python -m pip install pyinstaller
```

构建脚本会检查并下载英译中、中文译英两个离线模型，再把 Python 运行时、LibreTranslate 兼容本地翻译引擎、模型、Playwright 和 Chromium 一起装入绿色目录。模型下载只发生在开发机构建阶段，最终用户不需要安装 Python、Docker、LibreTranslate 或翻译模型。

生成位置：

```text
dist\tgexporter-portable\tgexporter.exe
dist\tgexporter-portable.zip
```

如果当前目录不是项目根目录，先进入项目目录：

```powershell
Set-Location "E:\PerSourceCodeStore\github\chengjinxt\tgexporter"
.\scripts\build_exe.ps1
```

## 启动方式

项目未安装到当前 Python 环境时，Windows 不能直接识别 `tgexporter` 命令，需要在项目根目录使用：

```powershell
python tgexporter.py listen
```

如果希望直接使用 `tgexporter listen`，先在项目根目录安装一次本地可编辑包：

```powershell
python -m pip install -e .
```

安装完成后可以运行：

```powershell
tgexporter doctor
tgexporter listen --channel TechnologyNewsSyncAssistant
```

`--channel` 会覆盖 `config.local.toml` 里的 `[telegram].channel`，只对当前命令生效。

也可以直接使用打包后的绿色目录。重新打包命令见上面的“打包绿色版”小节：

```powershell
.\scripts\build_exe.ps1
```

生成位置：

```text
dist\tgexporter-portable\tgexporter.exe
dist\tgexporter-portable.zip
```

绿色目录会把 Python 运行时、离线翻译引擎和中英模型、Playwright 驱动及 Chromium 浏览器一起放在目录内，不使用 onefile 自解压模式，因此每次运行不会再解压一大批文件到系统临时目录。公众号登录态默认保存在稳定的 `runtime\wechat-profile` 下；如果绿色目录还在项目 `dist` 下运行，会自动复用项目根目录的 `config.local.toml`、`data` 和 `runtime`。如果把绿色目录拷到别处使用，把 `config.local.toml` 放到 `tgexporter.exe` 同目录即可。

### 绿色版拷贝后的配置位置

把 `dist\tgexporter-portable` 整个目录复制到其他电脑后，推荐保持下面的目录结构：

```text
tgexporter-portable\
  tgexporter.exe
  config.example.toml      打包自带模板，不放真实 token
  config.local.toml        手动创建，真实生效配置
  data\                    自动生成，保存处理状态
  runtime\
    translation-models\   打包自带，保存离线英中双向翻译模型
    wechat-profile\        自动生成，保存公众号登录态
    wechat-profile-movie4k\ 自动生成，保存 4K影视屋公众号登录态
    source-profile\        自动生成，保存 X/微博等来源站点登录态
  发布内容\                自动生成或通过 --save-dir 指定
```

`config.local.toml` 不会自动生成，需要手动新建。最简单的方式是把绿色版目录里的 `config.example.toml` 复制为同目录下的 `config.local.toml`，再填入真实值：

```powershell
Copy-Item .\config.example.toml .\config.local.toml
```

常用配置说明：

- `[telegram].bot_token`：Telegram Bot token，必须配置。
- `[telegram].channel`：默认监听的频道号或频道用户名，例如 `TechnologyNewsSyncAssistant`；命令行里的 `--channel` 会临时覆盖它。
- `[telegram].proxy_url`：可选的 HTTP 代理地址。程序优先直连，直连失败时才尝试该代理和操作系统代理；新电脑代理端口不同时只需修改这里。
- `[output].base_dir`：默认保存根目录；`listen --save-dir "..."` 会临时覆盖它。
- `[wechat_accounts.default].profile_dir`：科技公众号后台浏览器登录态目录；保持默认相对路径时，会生成到绿色版目录的 `runtime\wechat-profile`。
- `[wechat_accounts.movie4k].profile_dir`：4K影视屋公众号后台浏览器登录态目录；第一次发布电影稿时需要单独扫码登录一次。
- `[source].profile_dir`：来源站点登录态目录，用于 X、微博、The Information 等需要登录的网站。
- `[tech_digest.translation].provider`：默认 `libretranslate`，直接使用绿色包内的离线模型，不需要 API Key。
- `[tech_digest.translation].model_dir`：离线模型目录；绿色版保持默认值即可。

`config.local.toml` 示例：

```toml
[telegram]
bot_token = "你的 Telegram Bot token"
channel = "TechnologyNewsSyncAssistant"
proxy_url = "http://127.0.0.1:7890"

[output]
base_dir = "发布内容"

[wechat]
profile_dir = "runtime/wechat-profile"

[wechat_accounts.default]
profile_dir = "runtime/wechat-profile"

[wechat_accounts.movie4k]
profile_dir = "runtime/wechat-profile-movie4k"

[source]
profile_dir = "runtime/source-profile"

[routes.movie4k]
output_subdir = "4K影视屋"
account = "movie4k"
cover_brand = "剪辑探索者"
batch_size = 2
match_usernames = ["dianying4K"]
match_titles = ["4K影视屋"]
```

配置优先级是：命令行参数最高，其次是 `config.local.toml`，最后是程序默认值。项目里的 `.env` 和系统环境变量不再作为程序配置读取。相对路径都会按当前识别到的运行根目录解析；绿色版单独拷走使用时，这个根目录通常就是 `tgexporter.exe` 所在目录，所以发布版的 `config.local.toml` 应放在绿色版根目录，也就是和 `tgexporter.exe` 同级。

检查配置和 Telegram Bot 连通性：

```powershell
python tgexporter.py doctor
.\dist\tgexporter-portable\tgexporter.exe doctor
```

`doctor` 会检查 Bot token，自动选择可用的直连/代理路径，并发起一次 Telegram Bot API 短轮询请求；输出中的 `Active connection` 会显示本次实际使用的是 `direct`、`configured proxy` 还是 `system proxy`。如果 `doctor` 正常但 `listen` 仍反复出现 SSL handshake timeout、unexpected EOF 或 read timeout，通常是当前网络路径的长连接不稳定；程序会自动降级为 5 秒短轮询继续重试。

## 监听 Telegram 新内容

第一版只处理程序运行后的新频道消息，不回溯历史消息。

启动一次监听轮询：

```powershell
python tgexporter.py listen --once --timeout 5
```

持续监听：

```powershell
python tgexporter.py listen
```

exe 版可以直接指定保存根目录：

```powershell
.\dist\tgexporter-portable\tgexporter.exe listen --save-dir "E:\PerSourceCodeStore\github\chengjinxt\tgexporter\发布内容"
```

`--save-dir` 是保存根目录，程序会在它下面继续创建日期子目录，例如 `20260718`，用于保存此次监听到的 Markdown、图片和视频。

绿色版一键全天草稿流程：

```powershell
Set-Location "E:\PerSourceCodeStore\github\chengjinxt\tgexporter\dist\tgexporter-portable"
.\tgexporter.exe --draft
```

`--draft` 会一直运行，监听新 Telegram 消息，并在当前绿色版根目录下使用：

```text
.\发布内容\YYYYMMDD
```

保存当天生成的 Markdown、图片和视频。生成文章后，程序只检查当天日期目录中尚未归档的 Markdown：每满 8 篇就立即打开公众号后台保存一条多图文草稿；如果当天一直不足 8 篇，但至少有 1 篇，到了本机时间 23:00 也会保存一条公众号草稿。过去日期目录不会被 `--draft` 自动处理，避免启动后误发布历史残留内容。以后每天重复同样逻辑。

每批草稿保存成功后，会把这一批 Markdown 以及 Markdown 引用到的本地图片、视频、附件移动到对应日期目录下的 `第1批`、`第2批` 等子目录，避免下次重复发布。`--draft` 会复用 `runtime\wechat-profile` 里的公众号登录态；第一次运行如果需要扫码，只在弹出的测试浏览器里登录一次即可。

如果消息来自 `4K影视屋(分屋）-蓝光无损电影` / `https://t.me/dianying4K`，`--draft` 会自动分流到：

```text
.\发布内容\4K影视屋\YYYYMMDD
```

电影稿使用单独公众号登录态 `runtime\wechat-profile-movie4k`，每 2 篇保存一条多图文草稿；科技稿仍使用 `runtime\wechat-profile`，每 8 篇保存一条多图文草稿。两个公众号第一次使用时都需要分别扫码登录一次。

持续监听时，如果 Telegram `getUpdates` 偶发网络读超时、SSL handshake timeout、unexpected EOF、连接重置或网关超时，程序会在直连、配置代理和系统代理之间选择可用路径，并打印 retry/网络排查提示后自动等待重试，不会因为一次网络抖动退出；未成功拉取的消息不会推进 offset，网络恢复后会继续处理。已处理过的消息会记录在 `data\state.sqlite`，后续重新运行也不会重复生成。

第一次正式监听前，如果频道里已经积压了旧更新，可以先丢弃当前队列，从下一条新消息开始处理：

```powershell
python tgexporter.py listen --drop-pending
```

只处理当前队列里最新一条，用于临时验证：

```powershell
python tgexporter.py listen --once --latest-only --timeout 3
```

运行后，把要发布的内容重新发送到 `TechnologyNewsSyncAssistant` 频道。程序会在：

```text
发布内容\YYYYMMDD
```

生成 Markdown、图片和视频文件。

Markdown 生成规则：

- 图片会放在文章标题下方、正文最上方，方便作为公众号封面和首图。
- 同一天同标题的 Markdown 已存在时，监听会跳过重复生成，并把本次 Telegram 消息号记录为已处理；即使状态库曾经丢失，也会扫描日期目录和已发布批次子目录避免重复写出 `013/014/015` 这类同标题文件。
- Telegram 正文里的频道推广行，例如“在花频道 / 茶馆水群 / 投稿通道”或“📢 频道 👥 群组 📝 投稿”，不会写入文章正文，也不会进入公众号正文。
- 来自 `4K影视屋` 的转发消息会按电影模板处理：标题会去掉资源帖里的 `名称：` 前缀和清晰度/码率/字幕标签，整理为“片名 + 年份 + 简短看点”的公众号标题；正文不会保留 `描述：` 这类字段名，也不会逐字照搬频道原文，而是重新组织为“影片导读 / 故事梗概 / 值得关注 / 影片资料 / 资源信息 / 资料来源”的原创公众号结构。`投稿: @pinuo_bot` 和 `Channel:...` 不写入正文；有视频会保存原视频，无图片时从视频中抽取关键帧生成封面，封面品牌字使用“剪辑探索者”。电影资源稿会额外尝试用片名和剧情字段检索 TMDB 中文页、IMDb、TMIOE、Rotten Tomatoes、豆瓣电影、猫眼、Netflix、维基百科等专业或官方资料页，IMDb 检索结果还会用于补足英文原名、年份、演员和海报。能获取时会补充片名、上映时间、类型、导演、主演、国家/地区、片长、评分、剧情简介、资料来源和海报候选；优先保留中文资料。资料不足的字段会直接省略，不会用未经来源支持的内容补齐。电影稿每 2 篇保存公众号草稿，保存成功后 Markdown 以及正文引用到的本地图片、视频会一起移动到 `第N批`。
- Telegram 隐藏链接默认会按“显示名称 + 空行 + URL”写入文末，例如来源名称下一行写完整链接；如果链接域名是 `mp.weixin.qq.com`，会保留在正文中作为公众号可点击超链接，不进入文末引用区。普通文本里的 `Tech 星球 (https://mp.weixin.qq.com/...)` 也会转换为 `[Tech 星球](https://mp.weixin.qq.com/...)`。
- 如果文章有视频但没有图片，会从视频中选择视觉信息更丰富的关键帧，生成同横竖方向的视频封面，并叠加 `firemail 科技频道` 和文章主题大字。
- 如果 Telegram 消息没有图片，会依次尝试引用网页配图、浏览器渲染截图、Google 图片兜底；网页配图会同时读取 OpenGraph 和正文图片候选。`mp.weixin.qq.com` 会额外提取页面里的 `mmbiz.qpic.cn` 图片作为配图候选。外部补图会跳过太小的图、近似方形 Logo、二维码、频道头像、纯色或渐变占位图，只保留第一张合格正文配图。仍然失败时才会生成一张本地 PNG 占位封面，保证每篇文章至少有一张图片。常见来源站点策略维护在 `docs\来源网站资源获取策略.md`。
- X、微博、The Information 等来源可能需要登录或订阅才能看到正文图片；Reuters 这类站点也可能要求人机验证。程序会在来源规则中记录登录/验证要求，抓图失败时按域名提示一次 `source-login` 命令。来源站点登录态默认保存在 `runtime\source-profile`，与公众号登录态分开。

## 采集网页教育资讯

`collect-web` 用于不经过 Telegram，直接从公开网站采集教育相关资讯并生成 Markdown。当前默认源组是 `chunhui-xuefu`，对应公众号“春晖学府”，默认抓取教育部官网工作动态。

运行一次，生成最新 1 篇：

```powershell
python tgexporter.py collect-web --group chunhui-xuefu --limit 1
```

exe 版：

```powershell
.\dist\tgexporter-portable\tgexporter.exe collect-web --group chunhui-xuefu --limit 1
```

定时常驻采集，每小时检查一次：

```powershell
python tgexporter.py collect-web --group chunhui-xuefu --limit 1 --interval-seconds 3600
```

也可以交给 Windows 计划任务定时运行一次命令。程序会把已采集 URL 记录在 `data\state.sqlite`，后续重复运行不会重新生成同一篇文章；默认只追最新增量，遇到最新已采集链接就停止向旧列表回扫。如果需要补采历史列表，显式加 `--backfill`。

```powershell
python tgexporter.py collect-web --group chunhui-xuefu --limit 5 --backfill
```

如果教育部原文没有合格配图，会生成带“春晖学府”品牌字样的教育资讯封面。

生成的 Markdown 仍保存在：

```text
发布内容\YYYYMMDD
```

后续发布方式不变：

```powershell
python tgexporter.py publish-wechat --article-dir ".\发布内容\20260719"
```

## 每日双语科技日报

`tech-digest` 是独立子命令，不会启动原来的 Telegram 监听、`collect-web` 或微信公众号流程。核心站点为 The Verge、TechCrunch、Ars Technica、Wired、Engadget、Tom's Hardware、ServeTheHome、Hacker News；备用站点为 IT之家、TechSpot、The Register、BleepingComputer。

程序优先读取各站的 `Most Popular`、`Most Read`、日榜或官方热榜。没有稳定阅读榜的站点按编辑推荐或首页文章顺序选择；Hacker News 使用官方 `topstories` 排名，并保存 score。默认每个核心站取 2 篇，站内继续向后补掉重复项；核心站不足时才用 4 个备用站补齐到每日 16 篇。历史已发布 URL、URL 跟踪参数和同一轮跨站相似标题都会去重。没有公开阅读数时只保存榜单方法和名次，不伪造访问量。

每篇科技日报都会保存并发布媒体。媒体选择顺序为：原文直链视频、原文 OpenGraph/正文图片、从原文视频生成封面、Google 图片搜索（浏览器模式可复用 `runtime/source-profile` 登录状态）、Bing 搜索兜底；如果搜索也不可用，程序会生成带文章标题的本地封面，确保不会出现无图文章。可直接下载且不超过 49 MB 的 MP4/WebM/MOV/M4V 视频会和图片一起保存在文章日期目录。Telegram 按模板只展示一个主媒体：有视频时优先以视频承载文章正文，视频不可用时自动回退图片；没有视频时直接展示图片。图片上限为 10 MB。

Telegram 科技文章采用固定模板：顶部为主视频或图片，正文依次为加粗中文标题、普通中文摘要、加粗英文标题、普通英文摘要；底部用 ` | ` 分隔来源网站、讨论页（如有）和原文链接，最后显示原文发布时间。摘要会从原文正文段落和结构化数据中提炼为两个自然段、三至四个完整信息句，覆盖主要事件、关键数字或技术细节以及原文提到的限制，不再把一条页面描述当作正文。抓不到足够正文的候选会被跳过并由同站后续候选或备用站补位。消息中不再展示批次序号和内部热度字段；热度依据仍保存在本地 Markdown 与 `manifest.json`。原文没有提供发布时间时会明确标记为来源未提供，不会用采集时间代替。

默认通过随绿色版一起发布的 LibreTranslate 兼容本地引擎生成双语标题和摘要。程序直接调用 LibreTranslate 所使用的 Argos Translate 推理层，不启动 Flask/HTTP 服务；因此不需要 API Key、网络、Docker，也不需要目标电脑另装 Python。第一次执行翻译时会加载本地模型，可能比后续翻译稍慢。

先验证绿色包中的运行时和两个方向的模型：

```powershell
.\tgexporter.exe translation-check
```

命令会实际完成一条英译中和一条中译英，并输出 JSON；它不是只检查文件是否存在。源码运行时可使用 `python tgexporter.py translation-check`。

如以后主动改用 OpenAI-compatible 接口，可把 `provider` 改成 `openai`，填写 `model`，并通过 `[tech_digest.translation].api_key_env` 指定的环境变量提供 API key。例如：

```powershell
$env:OPENAI_API_KEY = "你的 API key"
```

先做一次本地预演，不发送 Telegram：

```powershell
python tgexporter.py tech-digest --once --dry-run
```

确认内容后立即采集并发布：

```powershell
python tgexporter.py tech-digest --once --publish
```

每天上海时间 20:00 常驻运行并发布：

```powershell
python tgexporter.py tech-digest --watch --at 20:00 --publish
```

`--channel @频道名` 可只为本次科技日报覆盖目标频道；否则依次使用 `[tech_digest].target_channel` 和 `[telegram].channel`。发布前需要把 Bot 加为目标频道管理员并授予发消息权限。`--watch` 是常驻进程，终端或服务停止后不会自行唤醒；需要开机自启时可把这条命令配置到 Windows 任务计划程序或服务管理器。

当天 `published` 数量达到 `[tech_digest].daily_limit` 后，程序会在请求任何科技站点前直接结束，并输出 `daily limit reached (当前数量/每日上限)`，避免把无关的临时网络告警误认为本轮没有文章的原因。

需要重复验证同一天的真实发布流程时，可以显式清理该日期的 `published` 状态：

```powershell
.\tgexporter.exe tech-digest-clear-published --date 2026-09-26 --confirm
```

执行清理前应先停止 `tech-digest --watch` 等正在使用该数据库的进程。命令会先在 `data\` 下生成带时间戳的完整 SQLite 备份，再只删除指定日期且状态为 `published` 的记录；其他日期以及 `rendered` 等状态保持不变。不带 `--confirm` 时拒绝执行。清理后再次使用 `--publish` 可能向 Telegram 重复发送相同文章，因此该命令只用于受控测试；需要恢复时应先停止相关进程，再用命令输出的备份文件替换 `data\tech_digest.sqlite`。

本地文件与原流程分开保存：

```text
发布内容\科技日报\YYYYMMDD\
  01_标题.md
  02_标题.md
  ...
  manifest.json

data\tech_digest.sqlite
```

每篇 Markdown 同时保存中英文内容、来源 URL、真实榜单依据和实际发送给 Telegram 的 HTML 正文；`manifest.json` 记录本轮文件与发布状态。只有 Telegram 返回成功的 URL 才进入历史发布去重集合，因此预演或发送失败不会永久漏掉文章。

`--dry-run` 只生成本地 Markdown、图片/视频和 `manifest.json`，不会在 Telegram 频道留下发送记录。需要真正发送时必须使用 `--publish`；发送成功后 `manifest.json` 会记录 `telegram_message_id`。

## 公众号草稿辅助发布

对某篇 Markdown 打开公众号后台和本地预览：

```powershell
python tgexporter.py publish-wechat --article ".\发布内容\20260711\20260711_001_标题.md"
```

如果还没有安装 Playwright，命令会退回用默认浏览器打开本地预览和公众号后台。需要自动化浏览器时可安装：

```powershell
python -m pip install -e ".[wechat]"
python -m playwright install chromium
```

尝试自动填充公众号编辑器：

```powershell
python tgexporter.py publish-wechat --article ".\发布内容\20260711\20260711_001_标题.md" --auto-fill
```

一次发布多篇图文时，在 `--article` 后面连续写多个 Markdown 路径，最多 8 篇。第一篇会填到公众号最上面的主图文，后面的文件会依次点击“新建内容”追加到下面的子图文：

```powershell
python tgexporter.py publish-wechat --article ".\发布内容\20260711\20260711_003_字节跳动发布 Seedream 5.0 Pro，支持多语言生成与精准编辑.md" ".\发布内容\20260711\20260711_001_顶尖 AI 企业安全评级普遍偏低 榜首 Anthropic 仅获 C+.md" ".\发布内容\20260711\20260711_002_📱 华为 5G 旗舰重返海外，新机实测峰值速率突破 1100 Mbps.md" ".\发布内容\20260711\20260711_005_U-Boot 引导程序曝 6 个漏洞，可绕过验证在启动时执行恶意代码.md" --auto-fill --login-timeout 180 --review-timeout 600
```

也可以直接发布某个目录下的所有 Markdown/MK 文件，程序会按文件名排序，第一篇作为主图文。`--article-dir` 只遍历目录直接子级，不进入子目录：

```powershell
python tgexporter.py publish-wechat --article-dir ".\发布内容\20260716" --auto-fill --login-timeout 180 --review-timeout 600
```

exe 版常用命令：

```powershell
.\dist\tgexporter-portable\tgexporter.exe publish-wechat --article-dir "E:\PerSourceCodeStore\github\chengjinxt\tgexporter\发布内容\20260718"
```

如果已经进入绿色版目录，直接运行：

```powershell
Set-Location "E:\PerSourceCodeStore\github\chengjinxt\tgexporter\dist\tgexporter-portable"
.\tgexporter.exe publish-wechat --article-dir "E:\PerSourceCodeStore\github\chengjinxt\tgexporter\发布内容\20260718"
```

电影频道稿件发布到另一个公众号时，使用 `--account movie4k` 和电影目录：

```powershell
.\tgexporter.exe publish-wechat --account movie4k --article-dir ".\发布内容\4K影视屋\20260801"
```

`--account movie4k` 会使用 `runtime\wechat-profile-movie4k`。如果指定目录中混入了非 `movie4k` 的 Markdown，程序会停止并报错，避免发错公众号；默认不加 `--account` 时只发布 `account: default` 或旧版未标记账号的文章。

使用 `--article-dir` 时默认执行自动填充公众号草稿。如果目录下超过 8 篇 Markdown/MK，程序会按每批 8 篇自动分批发布；每一批保存草稿成功后，会把已发布批次的 Markdown/MK 以及文档引用到的本地图片、视频、附件移动到当前目录下的 `第1批`、`第2批` 等子目录。最后不足 8 篇的尾批也会在发布成功后移动到下一批目录。

`--auto-fill` 会打开一个 Playwright 管理的独立 Chromium 测试浏览器，浏览器登录态保存在：

```text
runtime\wechat-profile
```

它不是系统默认 Chrome/Edge 的用户目录，所以第一次使用时需要在这个窗口里扫码登录公众号。登录后再次运行 `publish-wechat --auto-fill` 会复用这个目录里的登录态，通常不需要重复扫码。

如果要手动打开同一个测试浏览器检查公众号后台和本地预览，不重新自动填充，可以运行：

```powershell
python tgexporter.py publish-wechat --article ".\发布内容\20260711\20260711_001_标题.md"
```

这个命令会用 `runtime\wechat-profile` 打开公众号后台和本地预览，并在终端等待回车。检查完成后回到终端按回车，脚本会关闭测试浏览器。

如果要重新自动填充，并保留窗口一段时间方便人工检查，可使用：

```powershell
python tgexporter.py publish-wechat --article ".\发布内容\20260711\20260711_001_标题.md" --auto-fill --login-timeout 180 --review-timeout 600
```

其中 `--review-timeout 600` 表示填充完成后保留浏览器 600 秒。检查时可以手动点击公众号后台的“保存为草稿”“预览”或“发表”。程序不会自动点击“发表/群发”。如果没有手动点击“保存为草稿”，关闭浏览器后公众号后台不保证会持久保存这篇内容。

自动填充后的调试文件：

```text
runtime\screenshots\wechat-auto-filled.png
runtime\screenshots\wechat-auto-fill-failed.png
runtime\wechat-preview
```

其中 `wechat-auto-filled.png` 用来快速确认标题、正文图片、封面和引用是否已经填入公众号编辑器。

当前公众号发布规则：

- Markdown 标题只写入公众号标题栏，正文里会跳过重复标题；公众号标题栏会自动去掉 emoji/图标字符。
- `.md` 和自定义 `.mk` 都按同一套公众号富文本规则转换，样式参考 `https://md.qikqiak.com/` 的“Markdown 预渲染后复制到公众号编辑器”思路，支持段落、二级/三级标题、引用、列表、分隔线、代码块、行内代码、加粗和超链接。
- Markdown 中的本地图片会按正文顺序逐张通过公众号“图片 -> 本地上传”插入正文。
- Markdown 正文里的 `[文字](https://...)` 会转换为公众号正文中的可点击超链接，`mp.weixin.qq.com` 链接也按这个规则保留。
- 封面优先从正文里刚上传的图片中选择，不再单独重复上传封面图。
- 本地视频不会直接插入为 `<video>` 控件；后续需要通过公众号视频号/素材视频流程处理。
- 多图文发布填充完成后会自动点击“保存为草稿”，但不会自动点击“发表/群发”；保存后仍建议人工检查、预览或发布。
- 自动化会在标题输入、图片上传、封面选择、新增子图文等步骤加入随机停顿，避免过快连续操作。

## 一键流程

监听新消息并在生成文章后打开公众号草稿辅助流程：

```powershell
python tgexporter.py run --draft
```

安全策略：

- 默认不自动发布公众号文章。
- 默认不点击群发。
- 公众号后台页面变化时，先使用本地预览辅助复制发布。

## 来源域名统计

程序会记录每篇文章的引用来源域名，完整链接仍保存在 Markdown 里，统计库里只按域名汇总。`mp.weixin.qq.com` 不会进入引用来源和统计，但正文里的公众号文章链接会以超链接形式保留。

如果来源站点需要登录，可先打开持久化来源浏览器：

```powershell
python tgexporter.py source-login --url "https://x.com/SpaceXAI/status/2076692402442846289" --timeout 600
```

exe 版：

```powershell
tgexporter source-login --url "https://www.theinformation.com/articles/deepseeks-annualized-revenue-nears-500-million-boosting-fundraise-ipo-plans" --timeout 600
```

在打开的浏览器里完成登录后，后续 `listen` 会复用 `config.local.toml` 里 `[source].profile_dir` 指向的 profile。`--timeout 0` 表示一直等到终端按回车。

查看来源域名排行：

```powershell
python tgexporter.py stats-domains
```

exe 版同样支持：

```powershell
tgexporter stats-domains
```

兼容误输别名：

```powershell
tgexporter stats-domainsstats-domains
```
## 2026-07-29 补充：一键草稿与软件分享规则

- `tgexporter --draft` 启动后只渲染本机当前日期的 Telegram 消息。若 Bot API 队列里还有昨天或更早的旧消息，程序会推进 update offset 并提示跳过，不会再把旧消息写入旧日期目录，也不会触发旧日期目录发布。
- GitHub 软件分享会优先识别仓库地址，标题整理为“软件名 - 主要功能说明”的形式。
- 软件分享正文不再直接复制英文 README 片段或命令行，也会过滤“为你撰写了一篇……”这类 AI 旁白；正文按第一原创作者口吻重写为“它能解决什么问题、快速上手、项目概况、实际效果、开源地址”等小节。
- 软件分享会优先下载 README 中的主图、截图和 GIF/图片资源；如果存在演示站，再抓取演示站截图作为补充。仍找不到合适图片时，才进入普通网页配图、截图、搜索图或本地占位图兜底。
