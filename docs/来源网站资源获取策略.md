# 来源网站资源获取策略

本文件用于维护常见信息来源域名的图片、视频获取方法，便于后续按站点补规则。

## 通用流程

1. 优先使用 Telegram 消息自带图片或视频封面。
2. 其次读取来源网页的 OpenGraph 图片和正文 `img` / 懒加载图片。
3. 下载网页图片时携带原文 `Referer`，避免部分站点防盗链失败。
4. 过滤 Logo、二维码、头像、频道图标、纯色或渐变占位图。
5. 如果网页没有合格图片，使用 Playwright 打开来源页，优先截取页面最大新闻图；`x.com`、`weibo.com`、`m.weibo.cn` 这类社交帖会优先截取单条正文区域，避免误取头像、侧边栏或无关素材。
6. 最后才使用 Google / Bing 图片搜索同标题相似配图，并过滤明显跑偏的素材站、Logo、猫图、成人/服饰素材和纯色占位图。
7. 默认在正文文末显示来源名称和完整地址，便于公众号读者点击原文；`mp.weixin.qq.com` 单独处理：不进入文末引用来源块和来源域名统计，但会保留在正文中作为可点击超链接，并从微信文章页面提取 `mmbiz.qpic.cn` 图片作为配图候选。
8. 对可能需要登录或订阅的来源站点，规则里记录登录要求；抓图失败时按域名提示一次 `source-login` 命令。

## 来源站点登录

来源站点使用独立浏览器登录态目录，默认是 `runtime\source-profile`。如果 X、微博或 The Information 提示登录/订阅，可先运行：

```powershell
tgexporter source-login --url "https://x.com/SpaceXAI/status/2076692402442846289" --timeout 600
```

在打开的浏览器里完成登录后，后续 `listen` 抓图会复用同一个 profile。`--timeout 0` 表示一直等到终端按回车。

## 本次问题原因

- 纯色蓝绿图片来自本地兜底占位图，说明当时没有获取到合格来源图。
- `weibo.com` 直接 HTTP 抓取会进入微博 Visitor System，因此拿不到新浪科技微博图片。
- `sohu.com` 文章的 `og:image` 是搜狐 Logo，正文若无合格图片，需要用正文截图作为封面。
- `bloomberg.com` 直接 HTTP 抓取会返回 403，浏览器能渲染出主图时应通过浏览器截取最大新闻图。
- `fifa.com` 正文图片由前端懒加载，普通 HTML 抽取不到图片；需要 Playwright 渲染和滚动后下载 `digitalhub.fifa.com` 正文图。
- `axios.com` 匿名 HTTP 可能 403 或进入 Cloudflare 验证；需要 Playwright 渲染后提取 `images.axios.com` 正文主图，若自动浏览器看到验证页，先运行 `source-login` 完成验证，避免退回本地纯色占位图。
- `theinformation.com` 的 DUV 光刻机文章普通 HTTP 元数据为空，但 Playwright 渲染后可拿到 `tii.imgix.net` 主图，应优先下载该 URL。
- `reuters.com` 在部分网络环境下会对自动浏览器返回空白页或 401；页面能正常打开时优先用 Playwright 提取正文图 URL，若被阻断则按提示先运行 `source-login` 完成验证。
- `ithome.com` 部分文章的 `og:image` 是 `images/v2/t.png` 站点占位图；旧版会把它当成候选后失败并退到本地生成图。浏览器提取到的正文图还可能带 `format,f_avif`，实际下载成 AVIF 后校验失败；现在会过滤占位图、清洗 AVIF 转码参数，并下载原始 JPEG 正文图。
- `wsj.com` 在自动浏览器里可能渲染出“访问暂时受限 / 我不是机器人”验证页；旧版有机会截图到错误页面，现在会识别为阻断页并提示 `source-login`，通过验证后再提取 `images.wsj.net` 正文图。
- 如果来源页无法取图，会优先走 Google/Bing 图片搜索；搜索结果会跳过 `stock.adobe.com`、`shutterstock.com`、`istockphoto.com`、`freepik.com`、`pinterest` 等素材站，避免再次出现与正文无关的猫图、服饰图或纯色图。
- 旧版移动批次文件时错误截断了带空格文件名，导致 Markdown 被移动进 `第N批`，但图片、视频仍留在父目录。
